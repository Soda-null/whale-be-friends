## Windows 上的 CI 红了

`install` 工作流的 Windows 一项从面板配色那次提交起就一直失败，是 `yu review` 的测试。修了 `scripts/review.py`，加了一个测试。

- **原因：** 复盘脚本打印中文，输出接到管道时 Windows 默认用 cp1252 这种装不下中文的编码，脚本崩溃退出。Mac 和 Linux 默认是 UTF-8，所以没事。
- **测试为什么没挡住：** 它设了 `PYTHONIOENCODING=utf-8`，但又加了 `-I`，而 `-I` 会让 Python 忽略这类环境变量，等于没设。
- **修法：** 脚本自己把输出定成 UTF-8。读它的人（ssh 到 Mac 的终端、面板）本来就按 UTF-8 读。新测试把编码故意设成 latin-1，三种系统都能抓这个毛病；两个测试失败时会把脚本的报错打出来。
- **没确认的：** CI 日志里没有脚本的报错原文，这个原因是推出来的：在 Mac 上用 latin-1 环境复现了同样的退出码 1，修后通过。要等推送后 Windows 那一项变绿才算真确认。测试也给子进程带上了 `SYSTEMROOT`（Windows 启动程序常需要的环境变量），防止它是第二个原因。
